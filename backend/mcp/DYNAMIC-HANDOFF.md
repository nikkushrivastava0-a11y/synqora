# Dynamic demo contract (local only)
Kanishk: use the same running local API (port 4317) and existing human-only Vite bridge. No separate database. Planner endpoint POST /api/workspaces/00000000-0000-4000-8000-000000000001/plan with {prompt, operationId} returns {success:true,data:{planId,revision,provider,model,createdAt,reviewTaskId,requirements,tasks,rawResponse}}. Each requirement has id,title,body,revision. Each task has id,title,status. All planned implementation tasks start open.
GET /api/workspaces/00000000-0000-4000-8000-000000000001/records includes the saved plan record (body is JSON). Gemini can read it via existing MCP read_record with recordId=planId, then claim reviewTaskId, submit_result with sources from get_sources, and reviews={recordId:planId,revision:1}. Plan record is an agent result, not a synthetic reviewer output. Use fresh operation UUIDs. Reviewer adapter owns its own files. For requirement change use existing POST /api/records/{requirementId}/revisions with operationId,expectedRevision,body,reason. Reload existing task board after writes. Do not mark implementation tasks completed just because a plan exists.
